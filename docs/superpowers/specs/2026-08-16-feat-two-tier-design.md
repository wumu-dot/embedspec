# FEAT 两级体系设计（父FEAT + 子FEAT）

- **日期**：2026-08-16
- **状态**：已确认
- **适用范围**：embedspec 可复用标准（复制到任意项目使用）

## 1. 背景与动机

现有 FEAT 体系只有一层：`docs/features/.template.md`（5 阶段：准备→设计→实现→测试→审查），
用于单次功能开发。但真实项目有**多级粒度**：一个大目标（如完整产品）→ 若干小阶段（里程碑）→ 每个里程碑内多个具体步骤。

用户需要一个**两级 FEAT 体系**：

```
大阶段（项目级目标）  →  项目本身，由 README / HANDOFF / docs/INDEX 承载，不建文档
        │
        ▼
小阶段 = 父FEAT       →  A1 / A2 / A3 …（统筹规划 + 项目表）
        │
        ▼
步骤 = 子FEAT         →  A1-01 / A1-02 …（每个走5阶段，带验收标准）
```

示例（SoundDog 项目，仅作演示，非模板内容）：
- A1 麦克风验证 → A1-01 接线验证、A1-02 I2S采集、A1-03 采样率校验…
- A2 RS485通信 → A2-01 硬件接口、A2-02 收发状态机、A2-03 协议帧…
- A3 上位机 → A3-01 框架+串口、A3-02 协议解析、A3-03 波形显示…

## 2. 核心设计决策（已确认）

| # | 决策点 | 结论 |
|---|--------|------|
| D1 | 文件组织 | 父FEAT = 计划表文档；子FEAT = 独立文档走5阶段 |
| D2 | 命名 | 父 `FEAT-A1-描述`；子 `FEAT-A1-01-描述`（字母=小阶段/目标，数字=子步骤序号） |
| D3 | 子FEAT流程 | 完整5阶段（复用现有模板）+ 停等 + 12条AC |
| D4 | 模板方案 | 方案A：独立 `.template-parent.md` + `.template-child.md`（原 `.template.md` 改名） |
| D5 | 可复用性 | 模板一律项目无关（`{{占位符}}`）；示例独立放 `examples/` 并标注"演示用，可删" |
| D6 | 示例内容 | 用 SoundDog A1/A2/A3 三组演示完整生命周期（不用做饭类比） |
| D7 | 大阶段归属 | 不建文档，落在 README（项目说明/当前状态/遗留问题）+ HANDOFF + docs/INDEX |
| D8 | 父FEAT状态 | 由项目表汇总：全子🟢→父🟢；有子🟡→父🟡；无子开工→父🔴 |
| D9 | 父FEAT生命周期 | 规划 → 人确认方向 → 逐个开子FEAT → 子阶段5通过回填 → 全🟢置父🟢 |

## 3. 文件布局

```
docs/features/
├── .template.md            → 改名 .template-child.md（子FEAT：原5阶段 + 父引用 + 回填规则）
├── .template-parent.md     → 新增（父FEAT：方向 + 项目表 + 依赖 + 阻塞 + DoD）
├── INDEX.md                → 两级索引模板
└── examples/               → 演示用，复制到项目后删除或改写
    ├── FEAT-A1-麦克风验证.md
    ├── FEAT-A1-01-接线验证.md
    ├── FEAT-A2-RS485通信.md
    └── FEAT-A3-上位机.md
```

> 示例为最小演示集：A1 父 + 1 个子FEAT 走完整5阶段；A2、A3 父FEAT只展示项目表结构。

## 4. 父FEAT模板 `.template-parent.md`（角色：Planner）

| 章节 | 内容 |
|------|------|
| 0. 元数据 | 优先级 / 预估总耗时 / 状态（🔴规划中→🟡部分完成→🟢全部完成） |
| 1. 总体目标与方向 | 核心目标一句话 + 大方向策略 + 硬边界（继承 CLAUDE.md） |
| 2. 项目表（子FEAT清单） | 子FEAT编号 / 功能 / 验收要点 / 优先级 / 依赖 / 状态 / 文件 |
| 3. 依赖与执行顺序 | 谁先谁后、可并行项 |
| 4. 阻塞与下一步 | 等硬件 / 待决策 / 下一步动作（对应"还需要我做什么？"） |
| 5. 完成定义（DoD） | 项目表全部🟢 = 父FEAT完成 |
| 6. 执行日志 | 时间/阶段/角色/摘要/遇阻 |

AI 执行规则：父FEAT 只做规划与统筹，不写实现代码；规划完成停等，人确认方向后才开子FEAT。

## 5. 子FEAT模板 `.template-child.md`（角色：Dev/Test/Review）

= 现有 `.template.md` 全部保留（5阶段 + 停等 + 12条AC），仅增量：

- 元数据新增一行：**父FEAT**：`FEAT-XX-…`（无父则填 `无（独立FEAT）`，保证单层项目也能用）
- 标题格式改为：`FEAT-A1-01-{简短描述}`（字母段继承父FEAT编号）
- 顶部规则新增一句：**阶段5通过后 → 回填父FEAT项目表该行 + 更新 INDEX.md**

## 6. INDEX 两级索引

```
| 层级 | FEAT ID | 优先级 | 描述 | 状态 | 文件 |
| 父   | FEAT-A1 | P1 | 麦克风验证 | 🟡 | … |
| ├子  | FEAT-A1-01 | P1 | 接线验证 | 🟢 | … |
| ├子  | FEAT-A1-02 | P1 | I2S采集 | 🔴 | … |
| 父   | FEAT-A2 | P1 | RS485通信 | 🔴 | … |
```

- 父子层级用 `├子` 前缀缩进表示
- 父行状态由子行推导（D8）

## 7. 状态流转

```
创建父FEAT（规划）
  → ⏸️ 人确认方向
  → 按项目表逐个创建子FEAT（各走5阶段，每阶段停等）
  → 子FEAT 阶段5通过 → 更新 INDEX 子行 + 父FEAT项目表该行
  → 项目表全部🟢 → 父FEAT置🟢（DoD达成）
```

## 8. 引用更新

| 文件 | 更新内容 |
|------|----------|
| `CLAUDE.md` | 场景导航表：规划方向→`.template-parent.md`；实现功能→`.template-child.md` |
| `docs/INDEX.md` | 场景表 + 文档清单：`features/.template.md` → 父子两模板 + INDEX + examples |
| `README.md` | 目录树 + 核心流程：补两级体系说明 |

## 9. 兼容性

- 已复制 embedspec 的项目：`.template.md` 改名 `.template-child.md` 是破坏性变更，但子模板内容与原名几乎一致（仅新增2处），迁移成本极低
- 单层项目仍可用：子FEAT填"无（独立FEAT）"即等价于旧模板
- 不涉及源码/脚本/CI，`check-doc-drift.sh` 不受影响
